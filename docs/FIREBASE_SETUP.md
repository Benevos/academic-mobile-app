# Firebase Setup for Calcula UAT Mobile

This document describes the Firebase configuration required by the Calcula UAT Android application v2.0.0.

Calcula UAT Mobile is developed with Flutter and Dart and communicates directly with Cloud Firestore through the Firebase Flutter SDK.

The mobile and web applications must use the same Cloud Firestore database.

---

## 1. Requirements

To configure the mobile application, developers require:

- a Firebase project;
- Cloud Firestore enabled;
- Flutter SDK;
- Dart SDK;
- Android SDK;
- FlutterFire CLI.

The Android application identifier used by Calcula UAT is:

```text
uat.uamm.calculauat
```

---

## 2. Create or select a Firebase project

Open the Firebase Console:

```text
https://console.firebase.google.com/
```

Create a new Firebase project or select an existing project intended for the Calcula UAT installation.

For independent reproduction of the software, developers are encouraged to use their own Firebase project rather than depend on the Firebase project used during the original research deployment.

---

## 3. Enable Cloud Firestore

Inside the Firebase project:

1. Open **Build → Firestore Database**.
2. Create a Cloud Firestore database.
3. Select an appropriate region.
4. Configure access rules appropriate for the intended deployment.

Calcula UAT uses the following principal collections:

```text
institutions
categories
problems
responses
```

The complete data model is documented in the web repository:

```text
https://github.com/Benevos/academic-web-app-v2/blob/master/docs/DATA_MODEL.md
```

---

## 4. Register the Android application

In Firebase:

1. Open **Project settings → General**.
2. Select **Add app → Android**.
3. Use the following Android package name:

```text
uat.uamm.calculauat
```

4. Register the application.

If Firebase provides a `google-services.json` file, place it at:

```text
android/app/google-services.json
```

The Firebase-generated file should contain the same Android package name:

```text
uat.uamm.calculauat
```

Do not manually invent or modify Firebase application identifiers.

---

## 5. Configure FlutterFire

Calcula UAT initializes Firebase using:

```text
lib/firebase_options.dart
```

This file is generated by the FlutterFire CLI.

For a new Firebase project, install the FlutterFire CLI in a local development environment:

```bash
dart pub global activate flutterfire_cli
```

From the root directory of the mobile project, run:

```bash
flutterfire configure
```

Select the Firebase project intended for the Calcula UAT installation.

Configure the Android application using:

```text
uat.uamm.calculauat
```

The process generates or updates:

```text
lib/firebase_options.dart
```

---

## 6. Verify Firebase identifiers

The Android configuration should be consistent across the project.

Verify:

```text
android/app/build.gradle
```

contains:

```text
namespace "uat.uamm.calculauat"
applicationId "uat.uamm.calculauat"
```

Verify that:

```text
android/app/src/main/kotlin/uat/uamm/calculauat/MainActivity.kt
```

contains:

```text
package uat.uamm.calculauat
```

If `google-services.json` is present, verify that its package name is also:

```text
uat.uamm.calculauat
```

Finally, verify that the Firebase options in:

```text
lib/firebase_options.dart
```

correspond to the same Firebase project used by the Calcula UAT web application.

---

## 7. Install Flutter dependencies

After cloning and configuring the project, dependencies can be installed locally with:

```bash
flutter pub get
```

The application can then be executed on an Android device or emulator with:

```bash
flutter run
```

These commands are intended for a local development environment with Flutter installed.

---

## 8. Firestore local persistence

Calcula UAT explicitly enables Cloud Firestore local persistence in:

```text
lib/main.dart
```

using:

```dart
FirebaseFirestore.instance.settings = const Settings(
  persistenceEnabled: true,
);
```

This allows Firestore to retain previously retrieved data locally and queue compatible writes while network connectivity is temporarily unavailable.

---

## 9. Offline behavior and limitations

The mobile application is designed to support intermittent connectivity.

Previously retrieved educational content may remain available from the Firestore local cache while the device is offline.

Interaction records generated during temporary loss of connectivity can be stored locally by the Firestore client and synchronized when connectivity returns.

However:

```text
Content that has never been retrieved by the device cannot be obtained from the cloud while the device is offline.
```

For this reason, Calcula UAT should be described as supporting intermittent connectivity or as offline-capable rather than as providing unrestricted offline operation.

---

## 10. Shared database with the web application

The expected architecture is:

```text
Calcula UAT Web
      |
      v
Cloud Firestore
      ^
      |
Calcula UAT Mobile
```

The web application creates and manages educational content.

The mobile application retrieves that content and records completed interactions.

The web application subsequently retrieves the interaction records for descriptive learning analytics.

Both components must therefore use the same Firebase project when they are deployed together.

---

## 11. Security considerations

Calcula UAT v2.0.0 is a research software prototype.

The current institutional access mechanism should not be interpreted as a production-grade authentication architecture.

Developers reproducing or extending the platform should:

- use a separate Firebase project for development or testing;
- avoid using real institutional passwords in demonstration databases;
- configure appropriate Cloud Firestore security rules;
- avoid storing sensitive personal information;
- migrate to a managed authentication mechanism before production-scale deployment.

Firebase configuration identifiers such as `apiKey`, `appId`, and `projectId` should not be treated as the primary security mechanism.

Data protection must rely on authentication, authorization, and appropriate Firestore security rules.

---

## 12. Verification checklist

Before testing the mobile application, verify:

- [ ] Cloud Firestore is enabled.
- [ ] The Android Firebase app uses package name `uat.uamm.calculauat`.
- [ ] `lib/firebase_options.dart` corresponds to the intended Firebase project.
- [ ] `android/app/google-services.json`, if used, corresponds to the same project.
- [ ] The web and mobile applications point to the same Firestore database.
- [ ] At least one test institution exists.
- [ ] Test categories and problems are available.
- [ ] No sensitive production credentials are being used.
- [ ] Firestore access policies are appropriate for the test environment.
